- 항목별 예산은 프로세스·티커·모델 변경과 무관하게 DB에서 공유한다. 신규 기사 전체를 하루 2회로 제한하는 것은 아니다.
- 실행기: PR #86에서 v9 복구. PR #89 배포 후에도 v9 다운로드와 health 커밋을 확인했다.

## 남은 문제와 판단 한계

1. 번역 검증 오탐: 중국어 `亿/万`, 시간 단위, `percent`와 `%`의 불일치, QNT 등 티커와 YOU 같은 일반 단어의 보호 규칙 문제가 재현됐다. 2회 제한은 과금 반복을 줄이는 변경이지 검증기 수정이 아니다.
2. AI 상세 오류 기록 부족: HTTP 오류·미완료 응답이 같은 예외로 묶이고 종료 사유가 보존되지 않았다. 출력 6,144토큰을 사용한 실패 증가분은 관찰했으나 모든 실패를 출력 한도 탓으로 단정할 수 없다.
3. 실패·기한 초과 항목이 다시 보강 대기로 잡히는 경로와 상태 시도 횟수 문제가 관찰됐다. 대기/포기 집계 증가와 실제 유료 호출 증가를 구분해야 한다.
4. DB Session Pooler의 `EMAXCONNSESSION`, `pool_size=15`를 마지막 조사에서 관찰했다. 앱 연결 설정은 수정하지 않았으며 해결 완료로 판단하지 않는다.
5. 테스트 계정 정리는 완료되지 않았다. `run_`/`lib_` 144개는 이름·이메일·해시·fixture로 대조했지만 닉네임 접두사만으로 다른 계정을 삭제하면 안 된다. 타 사용자 댓글 의존성이 발견되어 관련 데이터 삭제는 보류됐다.
6. CI 알림 스트림 테스트에서 시간 의존 실패가 한 번 발생했다. 같은 SHA 재실행은 통과했지만 테스트의 타이밍 취약성 자체가 고쳐진 것은 아니다.

- 게이트웨이 HTML 오류의 상태 유지, 제한된 GET 재시도, 프로필 수동 재시도·요청 시간 제한을 보완했다. 현물 필터 비교에서 거래 가능 USDT 490개를 유지하면서 응답 크기가 약 17.6MB→2.5MB로 줄었다.

- 차트 도구줄: 데스크톱 간격 28px, 1440/1100/390/320px 넘침·실행 오류 점검.

- 홈 커뮤니티 미리보기: 모바일 정적 목록, 데스크톱 호버 정지, 게시판 이동, 320/390/768/1099px 넘침 점검.

## 기록 유지 원칙

- 2026-09-30 사용자 승인으로 개별 활동 보고서 25개(후속 승인 문서 13개 포함), 원시 결과 40개, 점검 이미지 75개를 정리했다. 기존 결과·미해결 사항은 이 파일에 통합하고 실제 설계 문서·운영 안내·검증 스크립트는 유지했다. 추적 파일 원본은 Git 이력에서 복구할 수 있다.
- 후속 작업은 이 파일의 관련 항목을 갱신한다. 작업마다 보고서·배포 기록 파일을 새로 만들지 않는다.
- 변경 이유, 검증 범위, PR/커밋, 남은 문제만 남긴다. 실제 확인과 추정, 당시 기록과 현재 상태를 구분한다.
- 임시 스크린샷·전체 출력은 저장소 밖 임시 경로를 사용하고 작업 후 정리한다. 기존 검증 스크립트 일부는 docs 출력 경로를 사용하므로 실행 후 산출물을 남기지 않는다.
- 기존 운영/설계 문서와 검증 코드는 활동 기록과 구분해 유지한다. API 키·계정 개인정보·기사 원문 덤프를 이 파일에 옮기지 않는다.
