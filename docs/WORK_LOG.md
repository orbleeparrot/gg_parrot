- 웹의 국내 API 안내는 실행기부터 준비할 수 있게 한다. 키 준비 체크를 거래소 인증 성공으로 사용하지 않는다. 업비트의 공식 QR은 업비트 PC 웹 로그인용이며 API 발급·껄무새 권한 승인이 아니다. 빗썸 안내는 별도 이메일 활성화 절차가 아닌 API 2.0 발급·즉시 활성화 절차를 기준으로 통일한다. 실제 로그인·키 발급 녹화가 없는 상태에서 모식도를 실제 화면 영상으로 대체하거나 가장하지 않는다.
- 공식 근거: [업비트 키 발급](https://docs.upbit.com/kr/docs/api-key), [업비트 로그인](https://support.upbit.com/hc/ko/articles/11687872000537), [빗썸 API 2.0 발급](https://support.bithumb.com/hc/ko/articles/52815899880345), [업비트 전체 공개 명세](https://docs.upbit.com/kr/llms.txt), [빗썸 전체 공개 명세](https://apidocs.bithumb.com/llms.txt). OAuth·자동 키 발급·QR 키 인계의 공개 지원은 미확인이지 제휴 불가능이라는 결론이 아니다.
- 제휴 확인 사항: 사용자 승인형 연결 제공 여부, 허용 거래 권한·출금 제외, 키/토큰을 사용자 PC에만 보관하는 구조 지원, IP 등록 방식, 상업적 프로그램 제공 조건, 만료·철회 방식. 현재 약관의 직접 렌더링 대조와 해당 사업 조건의 서면 확인은 완료하지 못했다. 외부 사업자에게 문의를 전송하거나 제휴 신청은 하지 않았다. 로컬 암호화 저장만으로 약관 적합성이 보장된다고 안내하지 않는다.
- 기존 실행기 v10 릴리스·태그·체크섬·다운로드 주소는 유지한다. 새 도우미는 소스 구현이며 배포 바이너리에 이미 포함됐다고 표시하지 않는다. 배포하려면 별도의 새 불변 버전 릴리스가 필요하다.
- 최종 흐름: 국내 빠른 실행의 키 준비 체크를 없애고 ‘실행기부터 준비하기’로 진행한다. 바이낸스 게이트와 실제 실행 티켓 검증은 유지한다. 네이티브 도우미는 선택 매크로의 거래소·기존 키 변수만 사용하고 중복 메인 입력란을 숨긴다. IP 자동 조회는 열기 시에만 발생하며 성공/실패 120초 캐시·동일 진행 요청 공유·수동 재조회·조회 시각/주소 변경 안내를 제공한다. 공개 URL은 exchange/step만 보존하고 기존 `step=ip`는 첫 IP 단계로 호환한다. QR·모식도 및 전용 패키지 두 개는 제거했다.
- 안전성 보완: 도우미 확인·검사 완료·닫기는 매매 승인이 아니다. 도우미를 열면 이전 비동기 시작 의도를 폐기하며, 실전 확인/파일 출처 경고 모달 뒤에도 동일 설정·키·유효시간을 검증한다. 서버 실행과 봇에 같은 복제 snapshot을 넘기고 취소 시 새 서버 실행만 정리한다. 취소 통보 실패는 실제 매매 미시작과 구분해 표시한다. 종료 시 큐·IP 조회/유효시간 타이머를 정리한다. 최소 560×610·고밀도 화면의 모드 문구 잘림을 재현해 세로 배치·스크롤·고정 하단/키보드 이동으로 보완했다.

- 게시·정리: 기능 브랜치 `feat/exchange-connect-guide-1009`에만 커밋·푸시한다. PR 병합·운영 배포·실행기 릴리스는 하지 않는다. 기존 DPAPI 파일 형식·실행기 버전/다운로드·거래 주문 코드·운영 환경변수·회원/마이그레이션은 유지했다. 확인용 이미지 4개는 저장소 밖에서 검토 후 삭제했고 원시 결과나 별도 활동 보고서는 Git에 넣지 않는다.

### 후속 보완 · 신규 발급과 기존 키 재사용

- 사용자 재검토 요청으로 같은 PC 재시작·키 미저장·거래소 변경·새 PC·IP 변경·만료를 나누어 확인했다. 저장키 자동 복원과 발급 도우미 없는 시작은 이미 지원하지만, 도우미는 항상 신규 발급 첫 단계로 열리고 복원/수정/저장 실패가 구분되지 않았다. 검토 자체는 코드·운영을 변경하지 않았다.
- 전체 보완 승인을 받아 신규 발급/기존 키 입력/저장된 키 사용 동선을 분리한다. 웹의 준비 기록은 설치 감지가 아니라 사용자의 확인임을 유지하고, 이미 준비한 실행기는 다운로드 안내를 건너뛸 수 있게 한다. 모의 기본값·별도 실거래 확인·현재 설정에 대한 인증 검사와 실제 주문 없는 검사 경로는 유지한다.
- 거래소별 저장·삭제는 다른 거래소 키와 회원 키를 보존한다. 기존 v1/v2 파일과 DPAPI entropy는 유지하고 선택적인 관측 IP 메타데이터만 추가한다. 복호화/읽기 실패를 파일 없음과 구분하며, 실패한 기존 파일을 조용히 덮지 않는다. 저장 뒤 키를 바꾸면 저장 필요로 표시한다.
- IP 기록은 키 기억하기를 선택한 경우에만 기존 암호화 파일에 남긴다. 현재 저장키와 같은 키·모드·매크로에 대한 유효한 성공 검사와 신선한 공인 IPv4 조회가 모두 있을 때만 기록한다. 타 거래소·수정 중인 키는 암묵적으로 저장하지 않는다. 기록은 조회 서비스가 관측한 주소이며 실제 거래소의 등록 IP나 동일 라우팅의 증거가 아니다.
- 빗썸 `expired_jwt`는 요청별 JWT/시각 문제로, 실제 API 키 만료는 별도로 안내한다. [공식 인증 문서](https://apidocs.bithumb.com/docs/인증-토큰-생성하기)와 [키 관리 문서](https://apidocs.bithumb.com/reference/api-키-리스트-조회)의 1년·연장 불가 정책을 대조했다. 실제 거래소 키/계정/인증/주문은 테스트에 사용하지 않는다.
- 구현 완료: 저장된 완전한 키는 도우미의 검사 단계로 바로 진입하고, 미저장 기존 키는 발급 안내를 건너뛰어 입력한다. 웹의 준비 확인 기록은 실제 설치 감지가 아님을 표시하며 국내 재방문은 실행기 연결로 바로 진행한다. 바이낸스 키 준비 게이트는 유지했다.
- 저장·복구: 거래소별 저장/삭제에서 다른 저장 키·회원 키를 보존하고, 디스크의 최신 값을 기준으로 병합한다. 암호화는 고유 임시 파일·원자적 교체를 사용하며 실패 시 원본을 유지한다. 복원 불가 파일은 명시적 동의 후 같은 폴더에 암호화 원본을 백업하고 새로 저장한다. 다시 불러오기는 전체 미저장 변경을 확인하고 빈 회원 키도 저장값대로 복원한다. 설정·저장 동의가 확인창 중 바뀌면 작업을 취소한다.
- 통합 검토 보완: 저장/수정 상태 혼동, JWT와 키 만료 혼동, 큰 정수의 관측 시각 검증 오류를 회귀 테스트로 보완했다. 새/기존 키 선택 테두리를 실제 화면에서 검증했고, 메인 최소 창에서는 설정 영역만 스크롤하여 시작·종료 버튼을 고정했다. 로컬 키 삭제와 거래소의 키 폐기는 별개임을 안내한다.
- 최종 독립 검증: 운영 DB·거래소 인증·AI 키·주문 없이 백엔드 3,538 passed/5 skipped, Node 24 프론트 853 passed, lint 0 warnings/errors, 프로덕션 빌드 성공. 네트워크 차단 실행기 419개 OK/24 skipped이며, 건너뛴 실제 Tk 화면은 별도 HTTP/socket 차단 가상 화면에서 19개 모두 통과했다. Chromium 신규/기존 키·국내 재방문·바이낸스 준비 게이트·320/390/1440px·두 테마 등 20개 시나리오 통과, pageerror 0건이다. 확인창 중 저장 동의 변경 시 I/O 0회, 실패한 저장 원본 유지, 다른 거래소와 회원 키 보존도 회귀로 확인했다.
- SDK 호환성은 실제 python-binance 1.0.19·1.0.37 임시 환경에서 각각 419개 OK/20 skipped로 재확인했다. 건너뜀은 별도 검증한 가상 화면·Windows 환경 항목이며, 운영 의존성은 변경하지 않았다. 저장·복구 `eb90480b`, 실행기 화면 `f3f64cde`를 기능 브랜치에 게시했고 웹 안내·이 통합 기록도 같은 브랜치에 게시한다.
- 게시 범위: 기존 기능 브랜치에만 영역별 커밋·푸시한다. 새 실행기 불변 릴리스·운영 배포 포함 여부는 별도로 질문했으며 승인 전에는 기존 v10 태그·바이너리·다운로드와 운영 서버를 바꾸지 않는다. 실제 Windows DPAPI·새 exe·거래소 인증·사용자 발급 시간은 검증하지 않았다. 검증용 임시 이미지 두 장은 확인 후 삭제했다.
