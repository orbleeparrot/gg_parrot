## 남은 문제와 판단 한계

1. 번역 검증 오탐: 중국어 `亿/万`, 시간 단위, `percent`와 `%`의 불일치, QNT 등 티커와 YOU 같은 일반 단어의 보호 규칙 문제가 재현됐다. 2회 제한은 과금 반복을 줄이는 변경이지 검증기 수정이 아니다.
2. AI 상세 오류 기록 부족: HTTP 오류·미완료 응답이 같은 예외로 묶이고 종료 사유가 보존되지 않았다. 출력 6,144토큰을 사용한 실패 증가분은 관찰했으나 모든 실패를 출력 한도 탓으로 단정할 수 없다.
3. 실패·기한 초과 항목이 다시 보강 대기로 잡히는 경로와 상태 시도 횟수 문제가 관찰됐다. 대기/포기 집계 증가와 실제 유료 호출 증가를 구분해야 한다.
4. DB Session Pooler의 `EMAXCONNSESSION`, `pool_size=15`를 마지막 조사에서 관찰했다. 앱 연결 설정은 수정하지 않았으며 해결 완료로 판단하지 않는다.
5. 테스트 계정 정리: 2026-10-01 비밀번호 기반 397개와 Google 테스트 22개를 확인했다. 총 418개는 물리 삭제했고, 실제 회원 댓글 보존에 필요한 1개는 개인정보·비밀번호·회원 키를 없애고 탈퇴 처리했다. 생성 근거를 입증하지 못한 계정은 보존했다.
6. CI 알림 스트림 테스트에서 시간 의존 실패가 한 번 발생했다. 같은 SHA 재실행은 통과했지만 테스트의 타이밍 취약성 자체가 고쳐진 것은 아니다.

## 2026-10-02 — KRW 차트 표기·시세 정보 정리·거래소 전환 시 종목 유지

- KRW 현재가·시가/고가/저가/종가·가격축에서 불필요한 `.00`을 제거했다. 실제 소수 가격과 원본 봉 값·지표 계산은 보존하고, Binance USDT 표시 정밀도도 유지한다.
- 중복처럼 보인 줄은 원천 조회 시각과 선택 봉 시작 시각이었다. 조회 시각·캐시 상세는 기본 접힌 ‘시세 정보’로 옮겼다. 실제 현물/선물 출처, 선물→현물 대체, 시세 오류·지연·시장 불일치 경고는 접힌 상태에서도 표시한다.
- 기본 빌더와 빠른 가이드에서 대상 거래소 종목 목록을 공유 조회하여 상장된 동일 자산만 유지한다(`BTCUSDT ↔ KRW-BTC`). 미지원 종목·확인 실패·5분 이상 지난 국내 목록은 선택에 사용하지 않는다. 여러 자산은 지원되는 것만 남긴다. 금액·절대 가격과 국내 숏/선물 제약은 기존 초기화 규칙을 유지한다. 빠른 연속 전환 중 임시 빈 선택도 원래 자산 의도를 보존하며, 늦은 응답이 새 거래소·수동 입력·금액을 덮지 못하게 했다.
- 동료 원격 `b7b8b2d`의 공지 기반 개발자 노트 변경을 보존해 동기화했다. 최종 상태에서 Node 24 프론트 전체 **484개**, 프로덕션 빌드, 격리 Playwright 거래소 **7개**·시세 출처/자동 갱신 **8개**·종목 목록 **6개** 시나리오가 통과했다. 데스크톱/모바일·원화 OHLC·미지원 종목·연속 전환·경고 노출·구/신 응답 무조작 갱신을 확인했다. 실제 서비스 트래픽은 차단했고 운영 DB·유료 AI·실주문·실행기·환경변수·배포는 변경하지 않았다. 이미지·원시 출력은 Git에 추가하지 않았다.

## 2026-10-02 — 거래소 차트 보완·무조작 실시간 갱신

- 수정 범위는 거래소별 공개 차트·종목 목록·선택 입력과 가이드다. 현재 `design/round-2026-10-02` 브랜치에서 작업했으며 main 병합·운영 배포, 실행기 v9, 운영 환경변수·회원 DB·AI 과금 설정은 변경하지 않았다.
- 실시간 캐시 문제를 실제 공개 API로 재현했다. 3초 TTL이 만료되면 정상 백그라운드 갱신 중에도 `stale`이 반환되어 최신 봉 병합이 제외됐다. 업비트 35초 관찰에서 조회 예외 없이 11개 중 7개가 `stale`이었다. 최신 두 봉 캐시만 공유 갱신 완료를 기다리게 수정했고, 실제 실패·재시도 대기 때만 원래 유효기간 안의 이전 값을 반환한다. 다른 공용 캐시의 SWR·동일 요청 공유·재시도 제한은 유지한다.
- 새 프론트와 구 백엔드가 섞이면 `fetched_at_ms` 없는 구 응답이 모두 제외되는 문제도 재현했다. 구 `server_time`을 별도 가격 순서 근거로만 사용해 유효한 최신 가격은 갱신한다. 수집 시각으로 바꾸거나 수신 시각을 꾸미지 않으며, 원천 시각 없는 응답에는 LIVE를 표시하지 않는다. 오래된·미래·다른 출처·명시적 지연 응답은 계속 차단한다.
- 전체 봉과 최신 봉의 같은 출처 동시 응답이 서로를 폐기하지 않게 했고, 오래된 전체 봉이 이미 받은 최신 가격을 덮지 못하게 했다. 출처 전환은 별도로 무효화한다. 선물→현물 대체를 표시하고 두 시장의 봉을 혼합하지 않는다. 네트워크 오류·오래된 데이터·마감 확인 전 봉에는 LIVE를 표시하지 않으며, 탭 복귀 시 즉시 재조회한다.
- 가이드의 K·숏·레버리지 조건도 실제 선물 시장을 요청한다. 백테스트 차트·보조지표는 이후 편집된 폼이 아닌 테스트 당시 거래소·시장·봉 간격을 사용한다. 시간축·OHLC는 KST로 고정하되 원본 UTC timestamp와 거래소별 봉 시작 시각은 바꾸지 않았다. 폰트·차트 스타일은 유지한다.
- 국내 종목 목록을 서버·프론트 60초 단위로 갱신하고 HTTP 재검증을 적용했다. 마지막 성공 이후 총 5분이 지난 목록은 선택에 사용하지 않는다. 빈 목록·잘못된 원천 시각은 실패로 처리해 재시도 간격이 늘어나게 했다. 지연·실패 안내와 재조회 버튼을 추가했다. 지연된 종목 입력이 새 거래소·금액 조건을 덮는 문제와 AI 질문의 Enter 중복 선택도 막았다. `TUSDT`와 같은 한 글자 자산은 실제 거래소 목록 검증을 유지하면서 선택 가능하게 했다.
- 캐시 수정 후 실제 업비트·빗썸 KRW-BTC 화면을 각각 35초 동안 입력 없이 관찰했다. 최신 봉 응답은 각각 11개, 모두 HTTP 200·현물·`stale=false`였다. 업비트 가격과 캔버스는 자동 변경됐다. 빗썸은 그 구간 원본 가격이 동일해 가격·그림 변화 자체는 관찰하지 못했으나 원천 조회 시각은 매번 갱신됐고, 별도 공개 시간봉·분봉·[현재가 API](https://apidocs.bithumb.com/v2.1.0/reference/%ED%98%84%EC%9E%AC%EA%B0%80-%EC%A1%B0%ED%9A%8C)의 KRW-BTC 가격도 일치했다. 빗썸 웹사이트 자체 비교는 앞선 점검의 HTTP/2 접속 제한 때문에 완료로 주장하지 않는다. 현재 방식은 약 3초 REST 조회이며 WebSocket 틱 스트리밍이 아니다.
- 검증: 동료의 원격 `d45581e` 개발자 노트·게시판 공지 변경도 보존해 병합한 상태에서 백엔드 전체 2,449개, 프론트 전체 482개, 실행기 101개 중 100개 통과·1개 skip, Node 24 빌드 통과. 격리된 브라우저에서 구·신 응답 자동 갱신·캔버스 재그리기·초기 장애 복구·숨김/복귀·시장 혼합 차단·거래소 전환·종목 목록 만료를 검증했다. 개발자 노트 버전에 고정된 테스트 준비를 실제 닫기 버튼 사용으로 바꿔 새 공지도 테스트 입력을 가리지 않게 했다. 기존 전략/렌더러 154개 조합과 확대·이동·키보드·모바일 터치 회귀도 통과했다. 운영 계정·AI·주문 요청은 차단했으며 스크린샷·원시 결과는 Git에 추가하지 않았다.
