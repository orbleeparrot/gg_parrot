`design/round-2026-09-14`에서 [기존 감사](README.md)의 10개 항목을 보완했다. 공개 데이터 재사용, 계정 경계, 갱신과 무효화, 용량 제한을 함께 적용했다. 운영 배포·운영 DB 변경은 수행하지 않았다.

뉴스의 기사별 게시·증분 조회와 리더보드의 백그라운드 계산은 유지한다. 페이지 GET에서 뉴스 수집·번역이나 순위 계산을 실행하지 않는다. 응답 캐시가 비어 있으면 준비된 DB 결과를 먼저 읽어야 하므로 모든 첫 방문의 DB 대기가 없어지는 것은 아니다.

## 주요 캐시 정책

아래는 기본 설정이다. `stale` 추가 허용 시간은 정상 TTL이 끝난 뒤의 시간이며, 이를 넘으면 이전 값을 반환하지 않는다. 바이트 상한은 직렬화 크기로 관리하며 실제 프로세스 메모리 측정값은 아니다.

| 대상 | 정상 TTL / 갱신 | 만료 후 추가 허용 | 상한·무효화 |
|---|---|---|---|
| 공개 뉴스 서버 응답 | 1초 | 9초 | 256개·8MB, 같은 프로세스의 기사 변경 즉시 무효화 |
| 공개 뉴스 HTTP | 1초 | HTTP stale 별도 허용 없음 | ETag/304, 개인 응답 제외 |
| 리더보드 공용 snapshot 메타데이터 | 1초 | 없음 | 새 snapshot 게시 시 무효화, 회원별 권한·투표는 DB 조회 |
| 차트 과거 봉 | 간격별 60~900초 | 900초 | 256개·16MB, 같은 종목·간격·시장 데이터를 요청 개수만큼 잘라 반환 |
| 차트 실시간 봉 | 3초 | 15초 | 512개·2MB, stale 표시, 과거 봉 영구 저장과 분리 |
| 서버 종목 목록 | 6시간 | 24시간 | 목록 1개·1MB, 현물·선물 병렬 조회 |
| 환율 | 1시간 | 24시간 | 마지막 정상 환율·관측 시각·stale 상태 유지 |
| 과거 펀딩 | 과거 24시간 / 최근 5분 | 없음 | 128개·8MB, 부분 실패를 완료 결과로 캐시하지 않음 |
| 프런트 종목 목록 | 5분 | 빈 목록·stale 응답은 30초 뒤 재시도 | 숨겨진 화면 중지, 재활성화 시 확인 |
| 프런트 경주마 가격 | 45초 | 오류 시 기존 표시 유지 | 뉴스·하단 공용 구독, 실패 재시도 간격 최대 5분 |
| 프런트 뉴스 저장 | 최대 12시간 보관, 화면에서는 준비 상태에 따라 재조회 | 갱신 실패 시 기존 기사 유지 | 32개·1MiB, 저장 전 만료·오래된 항목 정리 |
| 프런트 채팅 | 새 메시지 증분 조회·표시 범위 재검증 | 날짜 전환 시 정리 | 회원별 1,000개, 비활성 계정 최대 3개·30분 |

캐시 무효화 중 이미 실행 중이던 응답이 도착해도 캐시에 다시 삽입하지 않는다. 백그라운드 갱신은 최대 8개 스레드·32개 예약 작업으로 제한하며, 각 캐시의 진행 중 키도 제한한다. 종료할 때 갱신 작업이 끝난 뒤 HTTP 자원을 닫는다.

## 적용 시 달라지는 점과 남은 측정 범위

- 이전 버전의 회원 구분 없는 임시 작업 초안은 소유자를 판단할 수 없어 복원하지 않는다. 새로 작성한 비회원 초안은 로그인한 회원에게 이전되고, 로그아웃 시 회원 초안은 정리된다. DB에 등록된 매크로를 삭제하는 변경은 아니다.
- 기존 `market.db`를 일괄 삭제하지 않는다. 검증 이력이 없는 봉은 해당 기간을 처음 요청할 때 다시 받으므로 최초 조회는 추가 수집 시간이 생길 수 있다.
- `render.yaml`에 `/var/data/market-cache`용 1GB 디스크와 환경변수를 선언했다. 실제 디스크 생성과 CDN 정책 변경은 배포 설정을 적용할 때 발생한다. 이 작업에서 리소스를 생성하거나 배포하지 않았다. 디스크는 해당 웹 인스턴스용이며 여러 인스턴스가 공유하는 메모리 캐시가 아니다. [Render 영구 디스크 문서](https://render.com/docs/disks)
- PWA는 빌드에 포함된 정적 자원과 일반 오프라인 안내만 저장한다. 회원 정보·뉴스 API·실제 페이지 HTML은 Cache Storage에 저장하지 않는다. 새 서비스 워커는 기존 탭이 닫힌 뒤 교체된다. [MDN 서비스 워커 수명주기](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)
- 공개 뉴스의 프로세스 간 변경 반영은 짧은 TTL과 후속 갱신으로 처리한다. 리더보드·뉴스의 내구성 있는 원본은 기존 공유 DB를 사용한다. 별도 Redis 서비스는 추가하지 않았다.
- `cache_performance` 로그에 hit/miss/stale, 실패·정리 횟수, 항목 수·직렬화 용량과 경로별 최근 p50/p95를 최대 60초마다 요청에 맞춰 기록한다. 회원 ID·캐시 키·응답 본문은 기록하지 않는다. **실제 운영 적중률·p95 개선 폭은 배포 후 측정 대상이며 이번 테스트 수치로 대체하지 않았다.**
