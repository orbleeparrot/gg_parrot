# main 통합 검증 — 2026-09-14

기준: 작업 브랜치 `8580468` + `origin/main`의 `828c9f3`. 최신 main의 6개 커밋을 merge 방식으로 통합했다. 원격 main의 기능을 제거하거나 작업 브랜치의 이력을 재작성하지 않았다.

## 유지한 main 기능

- 페이퍼 트레이딩의 종목별 자금 분배·매매와 합산 결과.
- 백테스트·페이퍼 시작·댓글 일일 퀘스트 및 프로필 퀘스트 표시.
- 매크로 파일 서명·출처 표시, 실행기 v7 소스와 서버 실행 로그.
- 헤더 회원 키 버튼과 기존 프로필 계정·보안 화면.

작업 브랜치의 리더보드 사전 계산, 뉴스 기사별 게시, 채팅 증분 조회, 캐시 보완, 빌더 종목 검색·포트폴리오 카드도 함께 유지했다.

## 통합 중 수정한 문제

| 문제 | 처리 |
|---|---|
| 두 브랜치의 Supabase 마이그레이션 버전 `20260914100000` 중복 | 이미 main에 있는 일일 퀘스트 버전은 유지하고 뉴스 enrichment 업그레이드만 `20260914130000`으로 이동. 전체 마이그레이션 번호 중복 검증 추가 |
| 새 개인 테이블의 앱 부팅 시 권한 보정 누락 | `dailyquestclaim`, `runsessionevent`를 RLS·공개 역할 권한 회수 대상에 포함 |
| 탈퇴 후 새 실행 로그·퀘스트 기록 잔류 | 기존 계정 정리 트랜잭션에서 삭제. 다른 회원의 기록은 유지하는 회귀 검증 추가 |
| 백테스트 시작 때 읽은 잔액이 이후 포인트 사용을 덮어씀 | 퀘스트 보상은 DB의 현재 잔액을 원자적으로 증가. 보상·원장·퀘스트 완료를 한 트랜잭션으로 처리하고 중복 요청은 롤백. 탈퇴된 계정에 보상 금지 |
| 헤더에서 키를 재발급해도 프로필에는 이전 키가 남음 | 같은 계정의 열린 패널은 메모리 상태를 공유. 재발급 전 GET과 늦은 타 계정 응답을 제외하고, 재발급 중 복사·중복 재발급을 방지. 마지막 패널을 닫으면 메모리 키 폐기 |
| 비ASCII 서명 값으로 실행 시작 API가 500 반환 | HMAC 형식 검증 후 비교. 편집된 파일은 기존 정책에 따라 `file_modified`로 처리 |
| CI의 단일 프로세스 Node 테스트에서 저장소 fixture 누출 | 테스트마다 localStorage·fetch를 설정·복원. CI와 동일한 `--test-isolation=none` 명령으로 확인 |

## 검증

- 백엔드 전체 **1,890개 통과**, 실패·오류 0: [결과](backend-results.json).
- 프런트 **281개 통과**, 실패 0: [CI와 동일한 명령의 전체 출력](frontend-tests.txt).
- 실행기 프로토콜 **58개 통과**, Linux에서 Windows named-pipe 통합 1개 건너뜀: [검증 요약](verification.json).
- 프로덕션 빌드 성공: [빌드 SHA-256](verification.json). 500kB 초과 청크 안내는 남아 있으며 빌드 오류는 아니다.
- 계정 전환·늦은 잠금 해제·초안 소유·회원 키 재발급: [브라우저 결과](account-browser.json).

백엔드는 임시 SQLite와 외부 네트워크 차단 상태에서 실행했다. 브라우저는 최종 빌드와 모의 API·WebSocket을 사용한다. 운영 DB에 마이그레이션을 적용하거나 실제 키를 재발급하지 않았다. 실행기 v7 태그·릴리스는 생성하지 않았다.

재실행 시 `CACHE_VERIFICATION_REPORT`로 백엔드 결과 경로, `ACCOUNT_BROWSER_REPORT`로 브라우저 결과 경로를 지정할 수 있다. 기존 캐시 감사의 수정 전·수정 후 증거는 덮어쓰지 않았다.
