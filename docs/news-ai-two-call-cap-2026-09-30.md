# 뉴스 AI 총 2회 제한과 호출 증가 조사

## 새 상한

- 제목 번역: 같은 정규화 제목당 최초 요청·교정·재시도를 합해 평생 최대 2회.
- 커뮤니티 요약: 같은 게시글 ID·본문 해시당 평생 최대 2회. 본문이 변경되면 새로운 입력이다.
- 서버·프로세스·티커가 달라도 DB 예약을 공유한다. 모델/프롬프트 변경과 재배포로 예약 횟수를 초기화하지 않는다.
- 기존 2회 이상 예약된 항목은 추가 호출하지 않는다. 2회째 성공한 결과는 그대로 재사용하고 실패 기사는 기존 표시 차단을 유지한다.
- 시장 요약: KST 하루 전체 서비스 공유 총 2회. 기존 환경변수 20이 남아 있어도 코드 상한을 올리지 못한다. 기존 예산과 성공 요약은 삭제하지 않는다.
- 공용 AI 런타임: 최초 1회 + 최대 1회 자동 재시도. AI_RETRIES나 호출별 override가 높아도 총 2회 이내이며, 기존 retries=0 경로는 1회 그대로다. OpenAI SDK 자동 재시도는 기존처럼 0.
- 새로운 기사/본문의 최초 호출 전체를 일일 2회로 제한한 것은 아니다. 백테스트/질문/종목 분석의 별도 일일 예산은 변경하지 않는다.

## 운영 관찰: 2026-09-30 17:07:42 KST

운영 Postgres에서 SET TRANSACTION READ ONLY와 transaction_read_only=on을 확인하고 SELECT만 수행했다. 유료 모델 요청은 만들지 않았다.

사용자가 본 2,257회 시점의 개별 호출 기록은 없어 정확히 그 숫자의 구성을 복구할 수 없다. 현재 집계는 위와 같으며, 자동 작업이 계속되는 중이라 관찰 시각마다 증가한다. 17:06에는 제목 1,227회·본문 1,031회였다.

호출 수는 배치 API 요청 단위다. 실패에는 공급자 오류/미완료 응답이 포함되지만 정상 응답 후 의미 검증 탈락은 모두 포함되지 않는다. 기사별 예약 합계는 한 요청 안의 여러 항목을 각각 세므로 API 요청 수와 같지 않다. 제공자 실제 청구서와 일치한다고 단정하지 않는다.

## 증가 원인

1. 신규 입력이 계속 수집된다. 오늘 처음 저장된 Binance Square 커뮤니티 글은 1,954개 기사 행이다(동일 글의 종목별 행 포함 가능). 외국어 제목 번역과 본문 요약이 별도 요청이다.
2. 기존 항목당 상한은 8회가 아닌 10회였다. 누적 예약 3~10회인 항목은 제목 227개, 본문 413개였다. 새 2회 상한은 이런 추가 반복을 차단한다.
3. 제목 검증 실패 시 최초 요청 후 교정 요청이 따로 실행된다. 이후 수집 회차가 다시 시도할 수 있었지만 모두 같은 평생 예산에 포함된다.
4. 이전 PR #88은 화면의 기사/커뮤니티 분리와 진단 개선이다. 커뮤니티 수집·AI 처리를 중단한 변경이 아니므로 기본 뉴스 화면에서 숨겨도 백그라운드 호출은 계속된다.
5. 이전 조사에서 확인한 검증기 오탐과 출력 한도 실패는 이 변경의 수정 범위가 아니다. 이번에는 그 실패가 반복 과금되는 상한을 낮춘다.

시장 요약 공용 예산은 이미 9회(Gemini 8회 + OpenAI 1회) 사용됐다. 이 예산을 0으로 되돌리지 않으므로 배포 후 오늘 추가 생성은 차단된다. 저장된 오늘 성공 요약은 계속 표시한다.

## 검증 범위

외부 네트워크 차단·격리 DB·가짜 공급자로 교정 포함 2회, 동시 워커 공유, 모델 변경/캐시 초기화 후 상한 유지, 기존 8회 예약 보존, 두 번째 성공 결과 재사용, 시장 요약 실제 총 2회, 높은 환경변수/override 우회 차단을 테스트한다. 운영 환경에서는 두 한도 변수만 변경하며 API 키·실행기 v9·모델/토큰 설정을 보존한다.
