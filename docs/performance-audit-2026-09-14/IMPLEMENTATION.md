# 리더보드·채팅·뉴스 성능 개선

수정 전 기준은 `9220067`, 감사 기록은 `1d86f78`이다. 이번 변경은 `design/round-2026-09-14`에서 구현했다. 운영 배포·운영 DB 변경·운영 부하 측정은 수행하지 않았다.

이후 기존 DB의 컬럼 추가 누락으로 발생한 뉴스 500 오류를 수정했다. 원인, 업그레이드 검증과 실제 개발 서버 복구 확인은 [NEWS_RECOVERY.md](NEWS_RECOVERY.md)에 기록했다. 아래 최초 개선 검증의 992개는 후속 업그레이드 테스트를 포함해 994개로 확장됐다.

## 조회와 준비 작업 분리

| 영역 | 변경 후 동작 |
|---|---|
| 리더보드 | 백그라운드에서 일일 이월·챌린지 생성·순위 계산 후 완료 스냅샷을 저장한다. GET은 스냅샷과 개인 투표·열람 권한만 조회한다. |
| 채팅 | 닫힌 창은 30초 간격으로 읽지 않은 수 등 메타데이터만 조회한다. 열린 창은 `after_id` 이후 메시지를 받는다. |
| 시장·종목 뉴스 | GET은 준비된 기사를 DB에서 읽는다. 수집·번역·요약·이미지 조회는 워커에서 수행한다. |
| 내 에이전트 뉴스 | 기사 단위로 원문·번역·분석을 저장한다. 준비된 기사와 이후 변경을 커서로 전달해 전체 수집 완료를 기다리지 않는다. |

### 리더보드

- 기본 5초 주기로 공용 순위를 계산한다. 여러 프로세스가 실행돼도 DB 임대를 획득한 작업자만 게시한다. 만료된 작업자의 결과는 반영하지 않는다.
- 새 스냅샷 전체를 저장한 뒤 현재 버전을 교체한다. 작업 실패 시 마지막 완료본을 유지한다. 최초 완료본이 없는 경우 GET은 `preparing: true`를 즉시 반환한다.
- 화면은 50개씩, API는 최대 100개씩 조회한다. 실행기·매크로 선택기는 같은 스냅샷에 고정해 전체 페이지를 조회한다. 공개 데이터에 매크로 비밀번호나 개인 열람 권한을 저장하지 않는다.
- 새 날짜·삭제 이후 페이지 수가 줄면 유효한 페이지로 이동한다. 채팅의 매크로 링크와 등록 직후 항목 찾기는 `entry_id`의 순위 위치를 인덱스로 조회해 해당 페이지를 연다. 이 이동 요청만 조회 1회가 추가된다.
- 투표 합계는 투표 변경과 같은 트랜잭션에서 저장한다. 구매·소유권은 읽을 때 확인한다. 왕관 집계도 백그라운드의 SQL 집계로 옮겼다.
- 이월 완료 표시와 이월 데이터 저장을 한 트랜잭션으로 처리한다. 챌린지 봇은 날짜·슬롯별로 기록해 부분 실패 후 중복 생성 없이 재시도한다.
- 수익률 원본은 기존 약 20초 주기의 모의매매 DB 체크포인트다. 화면에 반영되는 수익률에는 체크포인트와 순위 갱신 주기에 따른 지연이 있을 수 있다.

### 채팅

- 인증·메시지·읽음 상태 조회가 요청 세션 하나를 공유한다. 읽음 ACK는 기존 회원 잠금과 단조 증가 조건을 보존한다.
- 새 메시지가 한 번에 200개를 초과해도 중간 메시지를 건너뛰지 않고 다음 배치를 이어 받는다.
- 60초마다 현재 표시 범위를 확인해 삭제, 프로필 변경, 매크로 열람 권한 변경도 반영한다. 처음 표시되는 읽음 구분선으로 스크롤 위치가 변해 ACK가 누락되는 문제도 수정했다.
- 변경 없는 응답은 기존 객체를 유지한다. 한 번에 렌더하는 메시지를 최대 200개로 제한하고 이전·다음·최신 메시지 이동을 제공한다.
- 카운트다운을 별도 컴포넌트로 분리해 초 단위 갱신이 채팅 전체를 다시 그리지 않도록 했다.

### 뉴스

- `NewsArticleFeed`와 `NewsArticle`에 준비된 기사 및 변경 revision을 저장한다. 한국어 준비 전 원문을 먼저 저장하며, 제목 번역이 끝나면 다른 기사·소스·AI 분석이 끝나기 전에 공개한다.
- RSS 소스별, 브라우저 페이지별 완료 콜백을 추가했다. 기존 신선한 스냅샷이 있어도 새 기사 공개를 막지 않는다.
- 원문 재수집이 완료된 번역·분석을 덮어쓰지 않는다. 늦게 도착한 본문 분석은 본문 버전을 확인하고, 이미지 콜백은 현재 행의 이미지 필드만 갱신한다.
- 번역의 첫 응답에서 유효한 제목을 먼저 저장한다. 교정 요청은 누락된 제목의 실행권만 갱신한다. 번역이 미완료여도 GET은 준비된 한국어 기사를 즉시 반환한다.
- 미완료 제목·본문 요약 재시도는 DB 원문을 사용한다. 재시도 때문에 전체 수집처를 다시 호출하지 않는다. 여러 작업자의 중복 번역은 기존 공유 실행권과 배치 SQL로 방지한다.
- 만료 스냅샷·기사·요약 정리는 공유 임대를 사용해 시간 단위로 실행한다. 조회자가 없어진 공개 종목의 주기적 준비는 1시간 뒤 해제한다.
- 시장 이미지를 별도 React 상태에 보관하지 않는다. 같은 응답 경로로 기사·번역·이미지를 갱신해 과거 이미지 응답이 최신 번역 결과를 덮어쓰지 않게 했다.
- 준비 중 공개 뉴스는 3초, 완료 뉴스·이미지 대기는 30초 간격으로 확인한다. 에이전트는 3초 간격으로 변경분을 받고, 남은 배치는 짧은 간격으로 이어 읽는다. 외부 네트워크 오류에는 백오프를 적용한다.
- 모바일은 선택한 경주마 종목만 요청한다. 뉴스 갱신 시 사용자가 읽던 내부 스크롤 위치를 유지한다. 숨겨진 탭의 요청 중지·취소 동작을 보존한다.

## 로컬 검증 근거

아래 수치는 임시 SQLite와 고정 fixture의 실제 SQL·응답 크기다. 운영 PostgreSQL의 실행 시간이나 네트워크 전송 시간으로 해석하면 안 된다.

| 재현 조건 | 수정 전 | 수정 후 |
|---|---|---|
| 채팅 메시지 250개, 읽음 완료 후 변경 없는 열린 창 | SELECT 6회, 연결 3회, JSON 35,352바이트 | SELECT 3회, 연결 1회, JSON 376바이트 |
| 닫힌 채팅 | 3초마다 최근 200개 | 30초마다 메타데이터, JSON 380바이트 |
| 공개 시장/종목 뉴스 준비본 조회 | 수집·번역 대기 가능 | 각 SELECT 2회, 외부 작업 호출 없음 |
| 신규 제목 10개 실행권 획득 | SQL 40회 | SQL 2회 |
| 제목 10개 번역 저장 | UPDATE 10회 | UPDATE 1회 |
| 리더보드 120개 중 7개 조회, 개인 권한·투표 포함 | 전체 행 로드·투표 집계·정렬 | SELECT 4회, 모의매매 조회·요청 중 계산 없음; 인증 조회 별도 |

- [백엔드 회귀 결과](backend-regression-results.json), [실행 스크립트](verify_regressions.py): **992개 통과**. 뉴스·리더보드·채팅·챌린지·거래·공유 DB 세션을 함께 검증한다. 외부 소켓 연결을 차단하고 임시 DB만 사용한다.
- [채팅 SQL 재현](verify_chat_after.py), [채팅 브라우저 결과](chat-browser-results.json): **19개 시나리오 통과**. 회원 구분, 재방문, 탭 간 읽음 동기화, 새 메시지·삭제·권한 변경, 긴 이력, 미준비 매크로 선택기 재시도를 확인한다.
- [리더보드 브라우저 결과](leaderboard-browser-results.json): 실제 컴포넌트에서 페이지 축소, 채팅의 다른 페이지 항목으로 이동, 등록 직후 스냅샷 게시 대기 후 이동 **3개 시나리오 통과**. 이동 후 항목의 화면 노출과 키보드 포커스도 확인했다.
- [뉴스 브라우저 결과](../ui-checks/performance-2026-09-14/report.json): 320/375/767/768/1440px 및 밝은/어두운 테마, 선택 종목 요청, 오류 후 재시도, 준비 중 표시, 2.5개 기사 스크롤, 갱신 중 스크롤 유지 등 12개 시나리오를 확인했다.
- 프론트엔드 `node --test frontend/tests/*.test.js` 40개 테스트 파일과 Vite production build를 검증했다. 빌드는 배포하지 않았다.
- 지연된 소스·번역·시장 요약을 Event로 정지시켜도 준비된 기사 A가 먼저 조회되는지 테스트한다. 동시 임대·투표·제목 실행권, 오래된 작업자의 게시 차단, 스냅샷 실패 복구, 커서 중간 갱신도 검증한다.

## 배포 시 반영 사항

다음 세 SQL 마이그레이션을 함께 제공한다. 새 테이블은 RLS를 활성화하고 공개 역할의 직접 접근 권한을 제거한다. 이 작업에서는 운영에 적용하지 않았다.

1. `supabase/migrations/20260914092000_incremental_news_articles.sql`
2. `supabase/migrations/20260914093000_precomputed_leaderboard.sql`
3. `supabase/migrations/20260914094000_public_news_worker_lease.sql`

일반 실행에서는 `init_db()`가 새 모델을 등록하고 lifespan이 워커를 시작한다. `LEADERBOARD_BACKGROUND_ENABLED`, `PUBLIC_NEWS_EMBEDDED_ENABLED`, `POSITION_NEWS_EMBEDDED_ENABLED`가 모두 꺼져 있고 별도 워커도 없으면 준비본은 갱신되지 않는다. 기본값은 활성화다. Render의 bootstrap 모드도 RSS 및 제목 준비를 수행하고, 정기 브라우저·심층 분석은 기존 별도 워커 구성을 유지한다.

운영 반영 후에는 실제 p50/p95 응답 시간, PostgreSQL 실행 계획, DB 풀 대기, 워커 중복 실행 여부와 수집 지연을 측정해야 한다. 이번 로컬 검증만으로 운영 로딩 시간이 몇 초 줄었다고 주장하지 않는다.
