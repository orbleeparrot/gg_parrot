# 코인 동향 뉴스 500 오류 복구

2026-09-14, 성능 개선 후 기존 DB를 사용하는 개발 페이지에서 시장·종목 뉴스가 표시되지 않는 문제를 확인했다.

## 원인과 누락된 검증

`NewsArticle.enrichment_pending` 모델 필드를 추가했지만 기존 테이블에 해당 컬럼을 추가하는 시작 시 마이그레이션이 빠져 있었다. `CREATE TABLE IF NOT EXISTS` / SQLModel `create_all()`은 이미 존재하는 테이블의 컬럼을 보완하지 않는다.

실행 중인 서버에서 `/api/news/market`, `/api/news/coin/BTCUSDT`가 500을 반환했고, 같은 서버의 리더보드는 200이었다. PostgreSQL 카탈로그를 읽기 전용으로 확인하니 `newsarticle` 테이블에 `enrichment_pending` 컬럼이 없었다. ORM의 기사 조회에는 이 컬럼이 포함되므로 뉴스 조회와 수집 처리가 함께 실패했다. 앞선 새 DB 중심 회귀 검증과 모의 브라우저 API는 이 업그레이드 누락을 검출하지 못했다.

## 수정

- PostgreSQL·SQLite 시작 시 마이그레이션에 컬럼과 인덱스를 추가했다. 컬럼을 먼저 추가하고 인덱스를 만든다. 기존 기사 데이터는 유지한다.
- 기존 행은 한 번 재처리 대상으로 표시한다. 후속 기사 저장은 실제 번역·본문 요약 상태로 플래그를 갱신한다.
- 초기 SQL에도 기존 테이블 보완을 추가하고, 이미 초기 마이그레이션이 적용된 환경을 위한 `20260914100000_news_article_enrichment_upgrade.sql`을 별도로 제공한다.
- 갱신 실패 때 기존 기사를 숨기지 않도록 데스크톱·모바일 화면을 수정했다. 처음부터 받은 기사가 없는 요청 실패는 오류 상태를 유지한다.

## 확인 결과

- 수정 전 새 업그레이드 테스트 2개가 실패했다. 수정 후 기존 행 보존·반복 실행·컬럼과 인덱스 생성 순서를 포함해 통과했다.
- 백엔드 관련 회귀 테스트 **994개 통과**: [결과](backend-regression-results.json).
- 뉴스 큐 및 폴링 테스트 통과, Vite production build 성공.
- 갱신 실패 후 기존 기사 유지·재시도를 포함한 모바일·데스크톱 브라우저 **14개 시나리오 통과**: [결과](../ui-checks/news-refresh-error-2026-09-14/report.json).
- 실행 중인 개발 서버가 보완된 시작 시 마이그레이션을 적용한 뒤, 시장/BTC/ETH 뉴스의 **200 응답과 실제 준비 기사**를 확인했다. 개별 측정은 각각 약 0.97/1.15/2.18초였으며 부하 성능 벤치마크는 아니다.
- API를 모의 처리하지 않은 개발 페이지에서도 시장 뉴스와 당시 경주마 **10종목 모두 200 응답**, 준비된 기사 표시를 확인했다: [브라우저 결과](../ui-checks/news-recovery-2026-09-14/report.json), [화면](../ui-checks/news-recovery-2026-09-14/live-news-desktop.png). 운영 배포 상태를 검증한 결과는 아니다.
