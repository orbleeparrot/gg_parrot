# 뉴스 판단 테스트

- 페이지: `/admin/news-test` (관리자 로그인 필요)
- 진입: 관리자 → 뉴스 수집 현황 → 뉴스 판단 테스트
- 대상 모델: `semif-test:0.1.1`, Ollama `/api/chat` 호출

## 서버 연결

백엔드 환경 변수 `SEMIF_API_BASE`에 모델 서버의 기본 주소를 설정한다.
예: `http://model-host:11434` (끝에 `/api`를 붙이지 않는다).
인증이 필요한 프록시라면 `SEMIF_API_KEY`를 서버에만 설정한다.
`SEMIF_API_BASE`가 없으면 `OLLAMA_BASE_URL`, 그다음 `http://127.0.0.1:11434`를 사용한다.
Render에서 실행하는 경우 localhost는 Render 컨테이너 자신이므로 별도 GPU 서버의 접근 가능한 주소가 필요하다.
브라우저에는 모델 서버 주소나 인증 키가 전달되지 않는다.

상태 확인은 `/api/tags`에서 정확한 모델 태그가 존재하는지 검사한다.
연결 실패 시 테스트를 시작하지 않으며 다른 모델이나 임의 분류로 대체하지 않는다.
이번 작업 환경의 기본 Ollama 주소에는 연결되지 않았다. 실제 서버 주소가 확인되지 않아
실제 모델의 호환성·분류 결과·성능은 아직 검증하지 못했다.

## 처리와 시간 측정

기존 수집기가 DB에 저장한 뉴스만 읽으며 추가 수집·번역 요청은 하지 않는다.
시작할 때 최근 24시간 이내에 수집/갱신된 최신 20개 레코드를 가져오고,
대기열이 비면 커서로 새 레코드를 확인한다. 새 기사가 없을 때 확인 간격은 3초다.
번역 전 기사도 원제와 발췌로 분석할 수 있다. 동일 기사 ID는 피드가 달라도 중복 처리하지 않는다.

한 번에 한 기사를 판단하고 응답 즉시 결과를 표시한다. 완료 결과를 1.5초간 보여준 뒤
다음 기사를 처리하며 이전 결과를 사이드 목록으로 옮긴다. 호재·악재 외에 근거가 불분명하면 판단 유보를 허용한다.
프롬프트에는 수집된 제목/발췌만 포함되며 원문 전체를 별도 크롤링하지 않는다.

큰 숫자는 서버의 `perf_counter`로 측정한 **모델 HTTP 요청 시작 → 응답 수신·JSON 읽기 완료** 시간이다.
DB 조회, 사용자 인증, 화면 표시 대기, 브라우저 왕복 시간은 제외한다.
모델이 반환한 `total_duration`, `load_duration`은 나노초에서 변환하여 따로 표시한다.
추론 결과는 캐시하지 않으므로 다시 분석하면 실제 요청을 다시 보낸다.

중지/페이지 이동은 브라우저 요청을 취소한다. 서버는 연결 종료를 확인하고 모델 HTTP 요청도 취소한다.
이미 시작된 모델 내부 연산이 실제로 중단되는지는 모델 서버 구현에 달려 있다.
프로세스당 한 건으로 동시 추론을 제한하며, 모델 응답 대기 중 DB 연결을 유지하지 않는다.
실패한 기사는 다시 시작할 때 재시도한다.

기록은 현재 페이지 메모리에 최근 60건을 보관한다. 새로고침/페이지 이동 시 사라지며
운영 기사 분류나 DB를 변경하지 않는다. 모바일에서는 기록을 가로 스크롤 목록으로 배치한다.

## 검증

확인 결과: 신규 서버 테스트 13개, 전체 프런트엔드 단위 테스트 415개 통과.
프런트엔드 빌드 성공. Chromium에서 1440px 다크, 390px 다크, 320px 라이트의
시간 갱신·순차 분석·기록 이동·기록 열기·오류 중지·연결 실패·가로 넘침 검사를 통과했다.

- 격리 SQLite·외부 통신 차단: `backend/tests/test_news_sentiment_test.py`
- 순차 처리·중복 제거·새 뉴스·중지·재시작·60건 제한: `frontend/tests/newsSentimentTest.test.js`
- 실제 프런트엔드 빌드 + Playwright: `frontend/tests/newsSentimentBrowser.smoke.py`
- 이 폴더의 스크린샷/브라우저 결과는 **합성 기사와 가짜 모델 응답을 사용한 UI 검증**이다.
  스크린샷의 시간은 실제 `semif-test:0.1.1` 성능 측정값이 아니다.
