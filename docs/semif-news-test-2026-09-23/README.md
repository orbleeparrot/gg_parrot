# 뉴스 자동 판단 화면

- 경로: `/admin/news-test` (관리자 로그인 필요)
- PC·모바일 사이드바의 **뉴스 판단 테스트**, 또는 관리자 뉴스 수집 현황에서 진입
- 서비스: `semif-test:0.1.1` (SemIf 전용 `/v1/decide`, 포트 13000)
- 수동 시작·중지 버튼 없음. 페이지는 서버에서 진행되는 분석의 결과만 읽는다.

## 수집 → 자동 분석 → 화면

공통 뉴스 저장 함수 `upsert_articles`가 받은 모든 기사(시장/규제, 코인별 뉴스, 커뮤니티)를
기사 저장과 **동일한 DB 트랜잭션**으로 `NewsSentimentJob` 대기열에 추가한다.
최신 20건으로 제한하지 않는다. 같은 기사 ID는 여러 피드·번역 갱신·재수집에서 한 번만 등록된다.
최초 등록 당시의 제목/발췌를 모델 입력으로 보관하며, 원문 전체를 별도 크롤링하지 않는다.
배포 이전 기록 전체를 소급 분석하지는 않으며, 배포 이후 수집/갱신 경로로 들어오는 기사부터 대상이다.

FastAPI lifespan에서 시작한 작업자가 대기열을 한 건씩 처리한다. 대기 중 새 기사 확인 간격은 2초,
처리할 기사가 있으면 앞 기사의 완료 직후 다음 기사를 처리한다. 페이지를 닫거나 새로고침해도
처리는 계속된다. DB 리스와 토큰 검증으로 웹 프로세스가 여러 개여도 처리권은 하나만 갖는다.
모델 요청의 전체 제한은 95초, 리스는 120초이며 서버 재시작/비정상 종료 후 미완료 작업을 복구한다.
정상 완료는 중복 저장하지 않는다. 비정상 종료 직전에 모델이 응답했으나 결과 저장이 끝나지 않은
경우에는 복구 과정에서 해당 모델 호출이 재실행될 수 있다.

연결 장애는 전체 대기열에 백오프를 적용해 자동 재시도한다. 잘못된 응답은 기사별로 재시도하고
3회 실패하면 실패 기록으로 남겨 나머지 기사 처리를 막지 않는다. 호재/악재/판단 유보 결과를
임의로 만들어 채우지 않는다. 기존 사이트 뉴스 분류 필드와 매매 동작은 변경하지 않는다.

결과는 DB에 저장한다. 화면은 약 1.5초 간격으로 현재 처리/최근 결과와 이전 60건을 관찰한다.
변경 없는 요청은 버전 정보만 반환하며, DB에서는 작은 상태 행만 읽는다. 변화가 있을 때만
기사/결과 목록을 다시 읽는다. 통계는 작업 완료 때 누적하므로 매번 전체 테이블을 집계하지 않는다.
브라우저가 숨겨지면 화면 조회만 멈추며 서버 분석은 유지된다.

## 시간 측정

큰 숫자는 서버의 `perf_counter`로 측정한 **모델 HTTP 요청 시작 → 응답 수신·JSON 읽기 완료** 시간이다.
기사 수집, 큐 대기, DB 조회/저장, 화면 조회 간격은 제외한다. SemIf 응답의 `seconds`를 밀리초로 변환하여 모델 처리 시간도 따로 표시한다.
응답의 `choice`와 `probabilities`를 그대로 검증·표시하며 설명 문장을 임의 생성하지 않는다.
점수는 보정되지 않은 선택지 사이의 상대값이므로 실제 시장 상승/하락 확률로 표시하지 않는다. 진행 중 타이머는 서버 시간을 기준으로
계산하여 사용자 PC 시계 차이를 보정한다.

## 서버 설정

백엔드 `SEMIF_API_BASE`에 실제 모델 서버 주소를 설정한다. 이 GPU 서버에서 실행한다면 `http://127.0.0.1:13000`이다.
끝에 `/v1/decide`를 붙이지 않는다. 인증 프록시가 필요하면 `SEMIF_API_KEY`를 서버에만 설정한다.
`SEMIF_NEWS_ENABLED=false`로 소비 작업자만 비활성화할 수 있다.
모델 주소가 설정되지 않아도 수집된 기사는 대기열에 남으며, 화면에는 서버 설정 필요 상태가 나온다.
Render에서 localhost는 Render 컨테이너 자체이므로 외부 GPU 서버라면 접근 가능한 주소를 써야 한다.

시작 시 추가되는 테이블은 `newssentimentjob`, `newssentimentstate`이며,
기존 시작 마이그레이션을 통해 RLS와 브라우저 역할의 직접 접근 차단을 적용한다.
테스트는 임시 SQLite에서 실행하며 운영 DB에 접속하지 않는다.

### 실제 모델 확인 (2026-09-23)

사용자가 제공한 GPU 서버의 로컬 `http://127.0.0.1:13000`에서 `/openapi.json`, `/health`를 확인했다.
서비스 버전은 0.1.1이며, 모델은 `/models/Qwen3.5-4B`, dtype은 bfloat16이었다.
운영 사이트의 공개 시장 뉴스 3건을 가져와 **임시 SQLite 대기열 → 실제 SemIf 호출 → 결과 저장**을 검증했다.
HTTP 요청부터 응답까지 72.18 / 87.88 / 90.90ms, 모델 자체 처리 시간은 65.7 / 76.1 / 84.8ms였다.
세 뉴스는 모두 판단 유보로 분류되었다. 제목/발췌를 이용한 소규모 확인으로 성능이나 정확도 일반화를 하지 않는다.
실측 결과는 `live-pipeline-results.json`, 원시 응답 예시는 `live-model-response.json`에 있다.

제공된 외부 도메인의 13000 포트는 현재 작업 서버에서 HTTP·HTTPS 모두 연결 시간 초과였다.
로컬 포트는 0.0.0.0:13000에 바인딩되어 있다. 운영 Render에서 사용할 외부 접근 경로/프록시와
`SEMIF_API_BASE` 설정은 추가 확인이 필요하다. 로컬 성공을 운영 연결 성공으로 간주하지 않는다.
