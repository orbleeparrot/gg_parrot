## 사용자가 "왜 안 되는지" 를 못 보는 것

### 1. 프로 빌더 검증 결과가 필터를 말하지 않는다

`StudioPro.jsx:247-325` 가 쓰는 `main.py` 의 `_explain_facts` 가 숫자와 경고 코드만 넘기므로,
해설이 필터의 존재를 모른다. 필터를 조이면 거래가 줄고 검증이 "표본이 모자라다" 를 내는데,
**원인을 말해 주지 못한다.** 기본 빌더는 `explain.py` → `StudioDock.jsx:167` 로 정상 동작한다.

판정: 프로 빌더 리포트 확장은 프로 빌더 2차(전문가 조건·포트폴리오) 범위다. 1차에서
리포트 구조를 건드리면 그 작업과 충돌한다.

### 2. 합성(오프라인 데모) 데이터에서 거래량 필터가 항상 막힌다

`data/binance.py` 의 `_synthetic` 이 모든 봉의 거래량을 `0.0` 으로 낸다. 기준선 0 은
"거래가 없었음" 이므로 막힌다(설계대로). 사용자에게는 **"거래 0회" 로만 보인다.**

판정: 막는 것이 안전한 방향이고, 거래량을 지어내는 것은 그 파일이 가격에 대해 스스로
금지한 일이다. 고칠 것은 데이터가 아니라 **경고 문구**다 — 백테스트 결과가 이미
`source == "synthetic"` 를 알고 있으니, 거래량 필터 + 합성 데이터일 때 한 줄 띄우면 된다.

### 3. 재기동 때 과거봉 조회가 실패하면 조용히 거부한다

`paper.py:148-156`·`runner_engine.py:182-188`. 웜업 조회가 실패하면 차가운 필터로 되살아나
최대 400봉(1일봉이면 400일) 동안 말없이 새 진입을 거부한다. 순서(웜업 → 복구)는 맞고
행복 경로는 확인됐다. `state()` 에 웜업 상태가 없어 사용자에게 보이지 않는다.

판정: F·G·J 지표 규칙이 **이미 같은 노출**을 가지고 있다(필터 고유 문제가 아니다).
고칠 값어치는 있지만 "지표 상태를 사용자에게 보여 준다" 는 별개 작업이다.

### 4. 모순된 조합에 경고가 없다

`Builder.jsx` 의 "둘 다 맞아야 진입" 안내가 규칙 I 에만 있다. 정작 어긋나는 조합에는
교차 점검도 경고도 없다 — 예: 규칙 F 진입 RSI 30 + 조건 RSI 아래한도 50 ⇒ **영원히 안 산다.**
규칙 G 역추세 + 조건 볼린저 "밴드 안" 도 같은 성격.

판정: 규칙 params 와 필터 params 를 교차 검증하는 것은 새 기능이다. 다만 가장 사용자
친화적인 후속 작업 후보다 — "이 조합은 진입이 영원히 없습니다" 한 줄이면 된다.

## 기존 패턴의 반복 (필터만 고치면 비일관)

### 5. 기간 칸이 정수를 검사하지 않는다

`macro.js:278,281,290,295`(필터의 네 기간 칸)이 범위만 보고 정수 여부를 안 본다 →
`20.5` 를 프런트가 받고 서버가 거부, `api.js:118` 이 **영어 날 JSON** 을 그대로 띄우고
노란 칸 표시도 없다. **단 `rsi_period`·`grid_count`·`fast_period`·`ma_filter_period` 도
똑같은 틈이다.**

판정: 필터 칸만 고치면 네 개의 기존 칸과 비일관해진다. `Number.isInteger` 검사를
기간류 칸 전체에 한 번에 넣는 것이 맞다 — 그 자체로 작은 별개 작업.

## 설계·시험 쪽 빚

### 6. `FilterEval` 의 `else` 낙하

`entry_filter.py` 가 모르는 `kind` 를 조용히 거래량 필터로 취급한다. 스키마가 모르는
`kind` 를 거부하므로 API 로는 닿지 않지만, 스펙 §12 가 약속한 "`FilterKind` 에 값을
더하는 것으로 끝나도록" 을 깬다 — 2차에서 기준 종목 필터를 더할 때 조용히 거래량으로
동작할 수 있다.

판정: 닿지 않는 경로이지만 2차 작업 **시작 전에** 고쳐야 한다. 명시적 분기 + 모르는
kind 에 예외.

### 7. 아직 약한 시험 셋

- `test_entry_filter_sims.py` 의 "byte-for-byte unchanged" 는 실제로는 **결정성 시험**이다
  (같은 입력을 두 번 돌려 비교). 병합 기준점과 대조하지 않으므로 "예전과 같다" 를 증명하지
  않는다
- "둘 다 적용(AND)" 시험에 **두 관문이 동시에 참인 양성 대조**가 없다
- `note()` 가 "직전" 을 말하지 않는다 — 거래량 기준선은 직전 봉들의 평균인데 문구는
  "20봉 평균의 2배 이상" 이라, 차트 관례(현재 봉 포함)로 읽는 사용자와 문턱이 다르다

### 8. 문구·표기 미관

- 넓은 화면에서 진입 조건이 두 번 보인다 (구조화 칸 + 서버 요약 끝). 좁은 화면에서는

- `entryFilterPhrase`(JS)와 `note()`(파이썬)가 **같은 문구를 두 번 구현**한다.
  2026-10-06 기준 열 가지 경우에서 일치함을 확인했으나, 한쪽만 고치면 두 화면이 달라진다
