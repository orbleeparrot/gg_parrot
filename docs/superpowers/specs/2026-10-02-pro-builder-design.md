# 프로 빌더 1차 — 검증 중심 설계

작성 2026-10-02 · 상태 승인 대기

## 0. 한 줄 요약

전문가가 믿을 만한 **검증**과, 복잡해진 화면을 열어 주는 **코치 대화**를 붙인다.
백테스트 엔진은 한 줄도 고치지 않는다.

## 1. 왜 만드는가

- **전문가 유입 · 차별화** (주 목적). 전문 트레이더가 새 백테스트 도구를 볼 때
  가장 먼저 보는 것은 기능 수가 아니라 **검증 방식**이다. 워크포워드가 없으면
  그 자리에서 접고, 과최적화 경고가 있으면 "알고 만들었네"가 된다.
- **이탈 방지** (보조). 지금 빌더로는 한 번 만들면 할 일이 없다.
- **수명**. 조건을 늘리는 일은 "만들 수 있는 것"을 넓힐 뿐 한 번 쓰면 끝이다.
  검증은 **같은 전략을 계속 다시 돌려보게** 만든다.

## 2. 이번에 하는 것과 안 하는 것

1차는 **검증 중심**이다. 포트폴리오(종목별 다른 전략 · 가중치 · 상관관계)는 2차다.

포트폴리오를 뒤로 미루는 이유: 실행기가 단일 종목이라
(`runner/macro_runner.py` 의 `macro["symbol"]`, `backend/app/realtrade.py` 동일)
지금 넣으면 **짤 수는 있는데 돌릴 수는 없는** 기능이 된다. 전문가에게는 감점이다.
실행기 다종목 지원이 2차의 전제이며, 거래소 연동(업비트 · 빗썸) 작업과 겹친다.

## 3. 원칙

이 네 가지는 구현 중 흔들리면 안 된다.

| 원칙 | 뜻 |
| --- | --- |
| **엔진 불변** | 검증은 기존 백테스트를 여러 번 부르는 상위 레이어다. `engine/backtest.py` 를 고치면 기존 매크로 결과가 바뀐다. `engine/portfolio.py` 가 같은 패턴이다. |
| **판정은 서버, 설명은 AI** | 과최적화 경고는 결정론적 규칙이 낸다. AI 는 그 판정을 사람 말로 옮길 뿐 판정하지 않는다. |
| **분석은 좋은 말을 하지 않는다** | 수익률이 높아도 표본이 모자라면 그렇게 말한다. 칭찬하는 순간 장난감이 된다. |
| **자유 문자열은 프롬프트에 들어가지 않는다** | 대화형이지만 프롬프트 인젝션 면은 0 으로 유지한다. §5.3 |

"추천" 표현 금지는 기존 원칙 그대로다
(`docs/superpowers/specs/2026-09-23-ask-symbol-candidates-design.md` §2).
금지어를 `유망 · 안전 · 좋은 전략` 까지 넓힌다.

## 4. 검증

### 4.1 엔진이 이미 주는 것

| 값 | 쓰임 |
| --- | --- |
| `equity_curve` (ISO 시각 + 자산) | 구간 분해 · 낙폭 · 소르티노 · 칼마의 원천 |
| `sharpe` · `profit_factor` · `max_consecutive_losses` | 그대로 표시 |
| `buy_hold_return_pct` | 홀딩 대비 |
| `Period.start` / `.end` | **임의 구간 백테스트** — 워크포워드의 수단 |

### 4.2 백테스트 재실행 없이 되는 것

`equity_curve` 만 다시 읽는다.

- **수익 구간 분해** — 월별 수익. "전체 수익의 73% 가 2021년 2~4월에서 나왔다"
- **낙폭 구간과 회복 기간** — 가장 깊었던 구간이 언제였고 며칠 만에 회복했나
- **소르티노 · 칼마** — 칼마(연수익 / MDD)는 전문가가 먼저 본다
- **거래 집중도** — 수익의 몇 % 가 상위 몇 거래에서 나왔나

### 4.3 백테스트 N 회로 되는 것

`Period` 의 구간만 바꿔 기존 엔진을 다시 부른다.

- **워크포워드** — 기간을 4~6 등분해 구간별 성과
- **구간 안정성** — 구간별 수익률의 편차

### 4.4 과최적화 경고 (서버 규칙)

결정론적 판정이다. 아래 중 하나라도 걸리면 플래그를 세운다.

| 플래그 | 조건 |
| --- | --- |
| `한_구간_집중` | 한 구간이 전체 수익의 70% 이상 |
| `표본_부족` | 거래 10 회 미만 |
| `후반부_음수` | 워크포워드 뒤쪽 구간이 음수 |
| `거래_집중` | 상위 3 거래가 수익의 절반 이상 |

임계값은 구현 때 합성 곡선으로 조정한다(§10.1).

### 4.5 1차에서 빼는 것

**파라미터 민감도.** 백테스트 N×M 회라 비용이 다른 급이다. 2차.

## 5. 프로 물어볼까 (코치)

### 5.1 좁혀가는 대상

1. **전략 의도** — 어떤 시장을 가정하나, 추세인가 횡보인가, 얼마나 들고 있나
2. **규칙과 파라미터**
3. **검증 설계** — 어느 기간을 몇 구간으로 나눠 볼 것인가

3 번이 지금 위저드에 없고, 프로다움의 핵심이다.
*"6개월만 보면 이 전략은 한 국면만 겪습니다. 2년으로 늘리면 하락장이 포함되는데
어느 쪽을 보시겠어요?"*

### 5.2 턴 계약

```
서버 → AI   확정된 설정 · 아직 안 정한 항목과 각 항목의 허용값(풀) · 직전 선택
AI  → 서버   물을 항목 1 개 · 보여줄 값 3~5 개 · 문구 · "왜 묻는지" 한 줄
서버         금지어 · 길이 · 허용값 검증 → 통과분만 표시, 모자라면 폴백 문구
```

AI 는 값을 발명할 수 없다. 서버가 준 풀에서 고르고 문구만 쓴다.
`backend/app/ask_candidates.py` 의 구조를 그대로 쓴다.

선택지는 **3~5 개**. 10 개는 모바일에서 읽히지 않고, 억지로 채우느라 품질이 떨어진다.

### 5.3 자유 입력과 탈출구

- **선택지에 없을 때** — "다른 선택지 보기". 같은 질문에 다른 값을 새로 받는다.
- **타이핑이 되는 것** — 숫자 · 기간 · 종목처럼 **값이 유한한 것만**.
  서버가 정규값으로 해석한 뒤에만 전달한다
  (물어볼까 v2 의 "직접 고를래요" 종목 검색과 같은 방식).
- **의도 · 전략 같은 자유 서술** — 끝까지 선택지로만 받는다.

결과로 **사용자가 타이핑한 원문 문자열이 모델 프롬프트에 닿지 않는다.**
"자유 입력 없음" 원칙(`frontend/src/lib/askFlow.js`)을 글자가 아니라 효과로 지킨다.

### 5.4 쿼터

**세션 단위 1 회 차감.** 턴마다 차감하면 사용자가 말을 아껴 코치 경험이 망가진다.

- 세션 안 턴 상한 **20 회** — 비용이 아니라 남용 방지
- "다른 선택지 보기" 도 턴에 포함
- 백테스트 실행은 기존 체계 그대로

20 턴 세션도 월 수 달러다. 비용이 쿼터를 정하지 않는다.

## 6. 결과 분석 (AI)

### 6.1 입력과 출력

AI 에 넘기는 것은 **숫자와 플래그뿐**이다. `equity_curve` 원본은 넘기지 않는다.

```
입력:  수익 142% · 홀딩 38% · MDD 31% · 거래 14 회 · 칼마 1.2
       구간별 [+180%, +5%, -12%, +3%]
       상위 3 거래가 수익의 61%
       경고: [한_구간_집중, 후반부_음수, 표본_부족]
       근거: §7 이 모은 것

출력:  한국어 설명 3~5 문장 + 다음 수 선택지 3 개
```

경고 플래그가 있으면 **반드시 먼저 말한다.** 수익률을 앞세우지 못하게 한다.

### 6.2 쿼터 없음

입력 1K · 출력 400 수준이라 호출당 거의 0 원이다. 쿼터를 걸면 재검증을 안 하게 되는데,
재검증이야말로 수명의 원천이다. 대신:

- **결과 지표 해시로 캐시** — 같은 결과엔 같은 분석
- 분당 호출 상한만 남용 방지로

### 6.3 폴백은 폴백이라고 표시한다

AI 가 없거나 실패하면 서버 판정을 문장 템플릿으로 보여주되 **"AI 분석"이라 하지 않는다.**
일일 챌린지에서 템플릿이 "AI" 로 둔갑해 오래 들키지 않은 적이 있다. 로그에도 남긴다.

### 6.4 고리를 닫는다

```
빌더 → 검증 → 분석 → "이거 어떻게 고치죠?" → 코치 → 빌더
```

## 7. 근거

이상 구간을 뽑고 그 날짜의 성격을 가린다. 이상 구간은 **일간 변동이 그 구간 표준편차의
2 배를 넘는 날**로 잡고, 한 번에 보여 주는 것은 변동이 큰 순으로 최대 5 개다.
임계값과 개수는 구현 때 실제 곡선으로 조정한다.

### 7.1 1층 — 시장 대비 (항상, 전 구간)

| 데이터 | 출처 | 답하는 질문 |
| --- | --- | --- |
| 같은 날 BTC 변동 | 기존 klines | **시장 전체인가 종목 고유 사건인가** |
| 거래량 / 20 일 평균 | 기존 klines | 평소와 다른 일이 있었나 |
| 펀딩비 급변 | `data/binance.py` `fundingRate` | 선물이 과열됐나 |

뉴스보다 먼저다. "왜 올랐나" 보다 "시장 베타인가 알파인가" 가 앞선 질문이다.

### 7.2 2층 — 우리 DB (최근 30 일)

그 날짜 ±1 일의 기사 · 커뮤니티 글. 제목과 출처를 그대로 인용한다.
보존은 30 일이다(`collector.py` `retention_days=30`).

### 7.3 3층 — 과거 뉴스 조회

Google News 검색의 `after:` / `before:` 로 과거 날짜를 조회한다.
기존 페처(`_GOOGLE_NEWS`, 이미 `when:5y` 등 시간 연산자를 쓴다)를 쿼리만 바꿔 재사용한다.

2026-10-02 확인: `after:2026-03-13 before:2026-03-16` 으로 50 건이 돌아왔고
`pubDate` 가 전부 범위 안이었다.

### 7.4 조회가 아카이브를 채운다

3층에서 찾은 결과를 `NewsHeadlineArchive` 에 적재한다. 아카이브가 양방향으로 자란다.

- **앞으로** — 매일 수집분
- **뒤로** — 누군가 과거 날짜를 조회할 때마다

제목 · 날짜 · 출처 · URL 만 담으므로 행당 약 200 바이트, 하루 200 건이면 **연 15MB**.
본문 · 요약은 기존대로 30 일만 둔다.

### 7.5 지어내지 않는다

**근거는 AI 가 쓰지 않는다.** 서버가 찾은 실제 기사만 넘기고 AI 는 묶어서 설명만 한다.
못 찾으면 못 찾았다고 한다.

> "그 날짜는 뉴스 보존 범위 밖이라 근거를 찾지 못했습니다."

있지도 않은 기사를 그럴듯하게 만드는 순간 제품 전체의 신뢰가 깎인다.
수익률 숫자가 틀린 것보다 나쁘다.

### 7.6 한계

- **커뮤니티 과거 조회는 안 될 것이다.** 바이낸스 스퀘어는 `order=LATEST` 로만 받고
  날짜 파라미터가 없다. 구현 때 한 번 더 확인한다.
- **깊은 과거는 성길 수 있다.** 6 개월 전은 50 건이 나왔지만 2~3 년 전은 적어질 수 있다.
  §7.5 의 원칙이 그대로 적용된다.

## 10. 테스트

### 10.1 과최적화 판정 — 골든 케이스

`validation.py` 는 순수 함수라 결정론적이다. 합성 `equity_curve` 로:

- 명백한 과적합(수익이 한 구간에 몰림 · 거래 5 회) → **경고가 떠야 한다**
- 고르게 분산된 곡선 → **경고가 안 떠야 한다**

경고가 헛돌면 사용자가 무시하게 되고 기능이 죽는다.

### 10.2 불변식 — 자유 문자열이 프롬프트에 없다

AI 클라이언트를 가짜로 두고 **프롬프트를 통째로 캡처**해, 사용자가 타이핑한 원문이
어디에도 없는지 확인한다. 숫자 · 기간 · 종목은 정규값으로만 들어간다.

코드 리뷰로 지킬 수 없는 종류라 테스트로 고정한다.

### 10.3 그 외

- AI 가 풀 밖 값을 내면 버려지는지 (`tests/test_ask_candidates*.py` 패턴 재사용)
- 근거를 못 찾으면 AI 입력이 빈 배열이고, AI 가 지어낸 제목은 서버 검증에서 떨어지는지
- 금지어 확장(`유망 · 안전 · 좋은 전략`)이 걸리는지
- 폴백 분석이 "AI 분석" 으로 표시되지 않는지

- 실행기 다종목 → 2 차의 전제
- 커뮤니티 과거 조회 → 경로 없음 (§7.6)
