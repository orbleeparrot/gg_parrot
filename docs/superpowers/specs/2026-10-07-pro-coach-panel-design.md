# 프로 빌더 코치 패널 — 설계 (2026-10-07)

프로 빌더 2차의 **3/3**. 1차는 진입 필터(`2571e0b`), 2차는 포트폴리오 묶음.

## 1. 무엇을 만드는가

프로 빌더는 지금 **칸이 많은 판** 하나다. 규칙 열한 가지 · 규칙별 세부값 · 위험관리 · 진입 조건 ·
종목 비중 · 레그별 규칙 · 묶음 한도까지 열어 놓았으니, 처음 쓰는 사람은 **어디서 시작할지**를 모른다.

코치 패널은 옆에서 **좁혀 가는 대화**로 그 판을 채운다. 한 번에 하나씩 묻고, 답은
**3~5개 선택지**로 주고, 마음에 안 들면 `"다른 선택지 보기"`, 숫자·기간·종목처럼 고를 수 없는 것만
**좁은 입력칸**으로 받는다. 대화가 끝나면 조건 판이 채워져 있고, 사용자는 거기서부터 손으로 고친다.

**코치는 매크로를 만들어 주지 않는다 — 조건 판을 채워 준다.** 이것이 기존
"껄무새에게 물어볼까?"(`ask.py`)와의 결정적 차이다. 그쪽은 고정 설문을 받아 **완성된 매크로 3개**를
백테스트해 보여 주고 끝난다. 코치는 사용자가 계속 편집할 **폼 상태**를 넘긴다.

## 2. 지금 어떻게 되어 있나

- `frontend/src/pages/StudioPro.jsx` (328줄) — 한 줄로 쌓인 구조:
  `pro-chart`(차트) → `pro-build`(조건 판 = `Builder`) → `검증하기` → `pro-report`(검증 결과·근거).
  `StudioPro.css` 는 단일 열이다. 1행 주석이 이미 `"코치 패널 자리는 별도 계획에서 채운다"` 라고
  적어 두었다.
- `frontend/src/lib/macro.js` — `defaultForm()`, `withTypeDefaults(form, rt)`,
  `validateDetailed(form)`(첫 오류 하나 `{field, message}` 또는 `null`), `buildMacro(form)`,
  `macroToForm(macro)`. 폼 키는 전부 평평하다.
- `backend/app/ask.py` (929줄) — 재사용할 기계가 여기 다 있다:
  - 하루 한도: `daily_limit()`(`ASK_DAILY_LIMIT`, 기본 5), `remaining_today(db, user)`,
    `free_remaining_today`, `extra_left_today`, `buy_extra`(포인트로 추가 구매).
  - 동의: `consented(user)`, `give_consent`.
  - 세션 행: `AskMacroSession`(`user_id`, `day_kst`, `request_json`, `expires_ms`, `ask_count`,
    `paid`, …) — 하루 한도 키가 `(user_id, day_kst)` 다.
  - AI: `ai_available()`, `get_ai_client().messages.create(...)`, `ai_cache_key(...)`,
    `get_ai_runtime().call(key, load, retries=0)` — 캐시·재시도 정책을 공유한다.
- `ask.py` 가 세운 원칙이 하나 있고 이번에도 지킨다: **판정은 서버의 결정론적 규칙이 내고 AI 는
  제안만 한다.** `/api/validate` 의 docstring 이 같은 말을 적고 있다.

## 3. 설계 원칙

1. **대화의 뼈대는 결정론적이다.** 다음에 무엇을 묻는지, 선택지가 무엇인지는 서버의 **질문 그래프**가
   정한다. AI 가 정하지 않는다. 그래서 시험할 수 있고, AI 가 죽어도 코치가 돈다.
2. **AI 는 말투와 순서만 손댄다.** 한 줄 코멘트를 쓰고, 선택지의 라벨을 다듬고, 순서를 바꿀 수 있다.
   **선택지의 집합과 그 값은 못 바꾼다** — 그래야 코치가 만든 폼이 언제나 검증을 통과한다.
3. **코치가 내는 폼은 언제나 `validateDetailed` 를 통과한다.** 매 턴 끝에 서버가 그것을 보증한다.
   통과하지 못하는 조합은 선택지에 애초에 나오지 않는다.
4. **한도는 세션 단위다.** 대화 한 번이 1회다. 턴마다 깎지 않는다 — 좁혀 가는 대화에서 턴마다
   깎으면 사용자가 되돌아가기를 두려워한다.
5. **턴 상한에 닿으면 마무리한다, 끊지 않는다.** 남은 칸을 기본값으로 채우고
   `"여기까지 정했어요 · 나머지는 기본값으로 뒀으니 판에서 고쳐요"` 라고 말한다. 반쯤 채운 폼을
   던지고 멈추지 않는다.
6. **되돌아갈 수 있다.** 모든 턴의 답을 세션에 쌓고, 사용자가 앞 턴으로 돌아가면 그 뒤를 버린다.
7. **코치는 조건 판을 덮어쓰기 전에 묻지 않는다 — 대신 되돌릴 수 있게 한다.** 매 턴 적용 전 폼을
   세션에 남기고 `"되돌리기"` 를 준다. 확인 창을 턴마다 띄우면 대화가 아니다.

## 4. 질문 그래프

새 파일 `backend/app/coach.py`. 그래프는 **데이터**이고 코드가 아니다.

```python
@dataclass(frozen=True)
class Choice:
    value: str          # 이 선택지가 폼에 넣는 값(또는 patch 키)
    label: str          # 화면 문구
    patch: dict         # 이 선택지가 폼에 적용하는 것 — 평평한 폼 키만
    why: str = ""       # 한 줄 근거(AI 없이도 보여 줄 수 있는 것)


@dataclass(frozen=True)
class Question:
    key: str                     # 세션에 답을 쌓는 키
    ask: str                     # 코치의 질문(AI 가 없을 때 쓰는 문구)
    kind: Literal["choice", "number", "symbols", "period"]
    choices: tuple[Choice, ...] = ()      # kind == "choice" 일 때 전부(3~5개를 보여 주고 나머지는 더보기)
    field: str = ""                        # kind != "choice" 일 때 채우는 폼 키
    next: Callable[[dict], Optional[str]] = ...   # 답 묶음 -> 다음 질문 key
```

**노드 목록(1차 범위).** 각 노드는 선택지를 다섯 개까지 **한 번에 보여 주고**, 더 있으면
`"다른 선택지 보기"` 로 다음 묶음을 낸다.

| 순서 | key | 묻는 것 | kind |
|---|---|---|---|
| 1 | `goal` | 무엇을 하고 싶은가 (꾸준히 조금씩 · 추세를 타고 싶다 · 흔들릴 때 사고 싶다 · 자동으로 반복 · 직접 정하겠다) | choice |
| 2 | `risk` | 손실을 어디까지 견디나 (5% · 10% · 20% · 상관없다) | choice |
| 3 | `watch` | 얼마나 자주 볼 수 있나 (하루 한 번 · 몇 시간마다 · 거의 못 본다) | choice |
| 4 | `rule` | 위 셋에서 **좁혀진** 규칙 후보 3~5개 | choice |
| 5 | `symbols` | 어떤 종목 (좁은 입력 — 기존 `SymbolPicker` 재사용) | symbols |
| 6 | `weights` | 종목이 둘 이상이면: 균등 · 첫 종목에 더 · 직접 | choice |
| 7 | `period` | 어느 기간으로 볼까 (3개월 · 1년 · 3년 · 직접) | period |
| 8 | `capital` | 시작 자금 (좁은 숫자칸) | number |
| 9 | `entry_filter` | 진입 조건을 걸까 (안 걸기 · 이동평균 위 · RSI 과열 피하기 · 거래량 터질 때) | choice |
| 10 | `bundle_risk` | 종목이 둘 이상이면: 묶음 한도를 걸까 (안 걸기 · 동시 N종목 · 총 노출 M%) | choice |

`rule` 노드의 후보는 `goal`·`risk`·`watch` 에서 **결정론적으로** 좁힌다. 예: `goal=꾸준히` →
C(적립식) 우선, `watch=거의 못 본다` → 봉 간격이 긴 규칙과 D(그리드) 우선, `risk=5%` →
손절 기본값을 5로 두고 레버리지 선택지를 뺀다.

**그래프가 폼만 만지고 매크로는 만지지 않는다.** `patch` 의 키는 전부 `defaultForm()` 에 있는
평평한 키다. 그래야 프런트가 받아서 `setForm` 한 번으로 끝낸다.

## 5. 세션과 한도

`ask.py` 의 기계를 **그대로 재사용한다.** 새 테이블을 만들지 않는다.

- 코치 세션도 `AskMacroSession` 행이다. 구분은 `request_json` 안의 `"kind": "coach"` 다.
  (새 열을 더하면 마이그레이션이 생기고, 하루 한도 계산 `(user_id, day_kst)` 인덱스를 그대로 쓰는
  것이 더 값싸다.)
- **한 세션이 1회.** 세션을 **열 때** 한 번 깎는다(`remaining_today(db, user) <= 0` 이면 거절).
  턴마다 깎지 않는다 — 원칙 4.
- 턴 기록은 `candidates_json` 에 쌓는다(`[{key, answer, patch, at}, ...]`). 되돌아가기는 그 배열을
  자르는 것이다.
- `expires_ms` 로 세션 유효 시한을 둔다(기존 값과 같은 길이).
- 턴 상한 `COACH_MAX_TURNS = 14`(노드 10개 + `"다른 선택지 보기"`·되돌아가기 여유 4). 상한에 닿으면
  **마무리 턴**을 낸다 — 원칙 5.
- 동의(`consented`)는 기존 것을 그대로 쓴다. 코치가 AI 를 쓰므로 같은 고지가 필요하다.

## 6. 끝점

| 메서드 | 경로 | 하는 일 |
|---|---|---|
| POST | `/api/coach/start` | 세션을 열고 한도를 1회 깎는다. 첫 질문을 돌려준다. |
| POST | `/api/coach/answer` | `{session_id, key, answer}` → 폼 패치 + 다음 질문. |
| POST | `/api/coach/more` | `{session_id, key}` → 그 질문의 **다음 선택지 묶음**. 한도를 안 깎는다. |
| POST | `/api/coach/back` | `{session_id}` → 마지막 턴을 버리고 그 질문을 다시 낸다. 한도를 안 깎는다. |

응답 모양(네 끝점이 같은 모양을 쓴다):

```json
{
  "session_id": 123,
  "turn": 4,
  "max_turns": 14,
  "question": {
    "key": "rule",
    "ask": "이 셋이면 이 방식들이 맞아요. 어느 쪽이 마음에 들어요?",
    "kind": "choice",
    "choices": [{"value": "I", "label": "변동성 돌파", "why": "하루 한 번만 봐도 되고 …"}],
    "has_more": true,
    "field": ""
  },
  "form_patch": {"rule_type": "I", "candle_interval": "1d"},
  "done": false,
  "wrapped_up": false,
  "remaining_today": 4
}
```

- `form_patch` 는 **누적이 아니라 이번 턴의 것**이다. 프런트가 `setForm((f) => ({...f, ...patch}))`.
- `done: true` 면 대화가 끝났고 `question` 은 `null`. `wrapped_up: true` 면 턴 상한으로 마무리한 것이다.
### 폼이 언제나 유효하다는 보증 (원칙 3)

끝점이 요청마다 `Macro` 를 조립해 보는 방식은 쓰지 않는다 — 그러려면 `macro.js` 의
`buildMacro`/`defaultForm` 을 파이썬에 한 벌 더 베껴야 하고, 그 두 벌이 어긋나는 날이 온다
(1차의 `entryFilterPhrase`/`note()` 이중 구현이 바로 그 교훈이다).

대신 **그래프의 경로가 유한하므로 전수로 증명한다.**

- 선택형 노드의 선택지 수는 `5 × 4 × 3 × 5 × 3 × 4 × 3 = 10,800` 가지다. 입력형 노드
  (`symbols`·`period`·`capital`)는 대표값 하나로 고정한다.
- 그래프를 `frontend/src/lib/coachGraph.generated.json` 으로 내보내고, 백엔드 시험이 그 파일이
  **최신인지** 확인한다(`test_runner_release.py` 가 쓰는 것과 같은 패턴).
- 프런트 시험이 그 JSON 을 읽어 **모든 경로를 한 번씩 걸어** 폼을 만들고,
  `validateDetailed(form) === null` 과 `buildMacro(form)` 이 터지지 않음을 단정한다.

그래서 보증은 요청 때가 아니라 **빌드 때** 선다. 그래프에 선택지를 더하면서 유효하지 않은 조합을
만들면 그 시험이 바로 깨진다.

## 7. AI 가 손대는 자리와 그 한계

AI 는 **턴 하나의 말투**만 만든다. 입력은 `(지금까지의 답, 이번 질문의 key, 선택지 value 목록)`,
출력은 엄격한 JSON:

```json
{"ask": "…한 문장…", "labels": {"I": "…", "C": "…"}, "order": ["I", "C", "D"]}
```

서버가 받아서:

- `ask` 는 길이 상한(120자)으로 자르고, 비었으면 노드의 기본 문구를 쓴다.
- `labels` 는 **그래프에 있는 value 에 대한 것만** 받는다. 모르는 키는 버린다.
- `order` 는 **그래프의 value 집합과 같을 때만** 쓴다. 다르면 버린다(빠뜨리기·끼워넣기 차단).
- `ai_available()` 이 거짓이거나 호출이 실패하면 **노드의 기본 문구로 그냥 돈다.** 사용자에게는
  `"지금은 코치 말투 없이 안내만 해요"` 한 줄.

`ai_cache_key("coach-turn", _PROMPT_VERSION, model, payload)` + `get_ai_runtime().call(...)` 로
기존 캐시·재시도 정책을 공유한다. 같은 답 묶음에 같은 질문이면 캐시가 맞는다.

**AI 가 선택지의 값·집합·패치를 바꿀 수 없다**는 것이 이 절의 전부다. 그것이 원칙 2·3 을 지킨다.

## 8. 화면

`StudioPro.jsx` 를 두 열로 바꾼다. 새 컴포넌트 `frontend/src/components/CoachPanel.jsx`.

- **넓은 화면**(≥ 1100px): 왼쪽에 지금의 쌓임(차트·조건 판·결과), 오른쪽에 코치 패널(고정 폭 340px,
  스크롤 시 따라오게 `position: sticky`).
- **좁은 화면**: 코치 패널이 조건 판 **위**로 올라간다(접힌 상태로 시작, 머리말만 보인다).
- 패널 안:
  - 머리말 `"껄무새 코치"` + `"남은 횟수 N회"` + 턴 표시 `"4 / 14"`.
  - 대화 기록(지난 질문과 고른 답 — 한 줄씩, 되돌아갈 수 있게 각 줄에 `"여기로"`).
  - 지금 질문: 코치 한 줄 + 선택지 버튼 3~5개 + `"다른 선택지 보기"`(있을 때만).
  - `kind` 가 `number`·`period`·`symbols` 면 선택지 대신 **좁은 입력** 하나. `symbols` 는 기존
    `SymbolPicker` 를 그대로 끼운다(종목 검증·최대 5개가 공짜로 따라온다).
  - 바닥: `"되돌리기"`(마지막 패치 취소) · `"코치 그만하기"`.
- 코치가 패치를 적용하면 조건 판의 해당 칸이 **잠깐 강조**된다 — 무엇이 바뀌었는지 보여야 한다.
- 시작 전에는 패널에 `"무엇을 만들까요? 몇 가지만 물어보고 판을 채워 드려요."` + `"시작하기"` 하나.

## 9. 범위 밖

- **자유 서술 입력.** 코치는 선택지와 좁은 입력만 받는다. 자유 문장을 받으면 의도 해석이 AI 에
  들어가고, 그러면 원칙 1·2 가 깨진다.
- **코치가 백테스트를 돌려 비교해 주기.** 그것은 이미 "껄무새에게 물어볼까?" 가 한다. 코치는 판을
  채우고, 검증은 사용자가 `"검증하기"` 로 돌린다.
- **레그별 규칙을 코치가 정해 주기.** 묶음의 공통 규칙까지만. 레그별 규칙은 손으로 연다.
- **대화 이어가기(세션 복구).** 새로고침하면 세션이 끊긴다. 한도는 이미 깎였으므로
  `"아까 하던 대화가 있어요"` 로 되살리는 것은 후속.
- **실행기·실거래.** 코치는 폼만 만진다.

## 10. 1차에서 배운 것을 미리 반영한 자리

1. **문구가 화면에서 잘린다** — 코치 패널은 고정 폭 340px 이다. 선택지 라벨에 상한(28자)을 두고,
   근거(`why`)는 두 줄까지 접는다. 요약 끝에 붙이는 방식을 쓰지 않는다.
2. **백테스트와 실시간이 같은 답** — 코치는 폼만 만지므로 이 축이 비어 있다. 대신 **코치가 낼 수
   있는 모든 폼이 유효한지**를 전수로 증명한다(§6) — 요청 때 검사하는 대신 빌드 때 못 박는다.
3. **같은 문구를 두 번 구현하지 않는다** — 선택지 라벨과 근거는 **서버가 보낸 것만** 쓴다. 프런트에
   라벨 사전을 두지 않는다(1차의 `entryFilterPhrase`/`note()` 이중 구현을 반복하지 않는다).
4. **복구 경로** — 세션 복구는 범위 밖이지만, **한도를 깎고 나서 세션 생성이 실패하면 한도를
   돌려준다**(한 트랜잭션). 1차·2차에서 "경로 하나를 빠뜨려" 생긴 결함과 같은 자리다.
5. **시험이 무는가** — AI 가 선택지 집합을 바꾸려 할 때 서버가 버리는지, 턴 상한에서 마무리 턴이
   나오는지, 한도가 **턴마다가 아니라 세션마다** 깎이는지 — 이 셋은 돌연변이로 확인한다.
